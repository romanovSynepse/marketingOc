# Архитектура связки агентов SynOC

Версия 0.1 · 01.11.2026 · ТЗ для разработки конвейера Syneps.
Основа: `CLAUDE.md`, инструкция `brain/synoc-marketer-instruction.md` (разделы 6, 7, 17, 20–22),
документация `docs/SynOC_Reels_Pipeline_DevDoc.pdf`.

---

## 1. Что строим

**SynOC — оркестрация, а не движок генерации.** Claude — мозг и дирижёр: думает, решает, пишет,
проверяет и управляет конвейером. Глаза, уши и руки — внешние сервисы (данные, транскрипция,
генерация, публикация).

Цикл: **найти, что работает → вытащить сценарий → переписать голосом бренда → утвердить →
произвести → опубликовать → измерить → улучшить отбор**.

### Принципы

1. **Данные и транскрипцию покупаем; отбор, разбор, рерайт и замкнутый цикл — свои.** Это ценность и защита продукта.
2. **Человек утверждает сценарий до генерации.** Ни одного платного вызова генерации без утверждённого сценария и сметы.
3. **Каждый сценарий опирается на прецедент.** Агенты не выдумывают идеи «от себя».
4. **Клонируем структуру, не чужие материалы.** Без копии 1:1, без выдуманных результатов, без накруток.
5. **Каждый шаг пишет результат в базу.** Агенты общаются через данные, а не через память чата. Любой шаг можно перезапустить.
6. **Дешёвая модель там, где хватает.** Дорогая — только для сценариев и стратегии.
7. **Честные цифры.** Нет данных — агент так и говорит; пороги — «ориентир рынка».

## 3. Агенты

Для каждого: **вход → выход**, инструменты, модель, когда запускается, критерии качества.

### 🎼 A0. Оркестратор
- **Роль:** ведёт каждый объект (бренд, ролик, сценарий, публикацию) по статусам, ставит задачи
  агентам, следит за лимитами API и бюджетом, повторяет упавшие шаги.
- **Инструменты:** Supabase (статусы, очередь задач), планировщик (cron / pg_cron / воркер).
- **Модель:** не нужна (обычный код). LLM — только для разбора нестандартных ошибок.
- **Правила:** бюджет генерации на бренд в день/месяц; стоп при превышении; лог каждого платного вызова.

### 🔭 A1. Скаут — найти блоги
- **Вход:** бренд: ниша, сегмент, язык, регион, 3–5 примеров «как мы хотим».
- **Выход:** таблица `accounts`: handle, площадка, подписчики, медиана просмотров, релевантность 0–1, причина.
- **Инструменты:** HikerAPI (основной), ScrapeCreators (поиск по хэштегам), Apify (резерв), Exa (статьи
  и подборки), vidIQ `ig_accounts_from_outliers`, база референсов (`brain/`, ~350 аккаунтов).
- **Модель:** Haiku / Gemini Flash — чистка списка по био и подписям.
- **Запуск:** при подключении бренда; дальше раз в неделю добор.
- **Качество:** аудитория (язык, регион, культурный контекст) совпадает с ЦА бренда; отбор не по расе,
  национальности, религии.

### 📈 A2. Аналитик вирусности — найти вирусные ролики
- **Вход:** `accounts`.
- **Выход:** `reels` + `reel_snapshots` (замеры на 6 / 24 / 72 ч); флаг `candidate` у прошедших отбор.
- **Инструменты:** HikerAPI (просмотры, лайки, комменты, **пересылки, репосты**), Supabase.
- **Модель:** не нужна — формулы:
  - выше нормы = просмотры ÷ медиана последних 20–30 роликов; **> 3× → кандидат**;
  - аномалия = просмотры ÷ подписчики;
  - скорость = прирост просмотров в час за первые 24–72 ч;
  - виральность: репосты ≥ 10% от лайков; вовлечение: комменты ≥ 1% от лайков;
  - накрутка: аномально мало лайков/комментов на такие просмотры → выкинуть.
- **Табу (раздел 7 инструкции):** реклама брендов, всё держится на конкретном человеке/звуке/танце,
  ситуативные и школьные тренды, маски TikTok, статика с текстом, несовпадение аудитории.
  Табу-фильтр — Haiku по описанию и кадрам.
- **Запуск:** каждые несколько часов.

### 🔬 A3. Разборщик — вытащить сценарий
- **Вход:** `reels.candidate = true`.
- **Выход:** `breakdowns` (формат — раздел 5.1): транскрипт с таймкодами, текст на экране, визуал,
  структура (хук, удержание, место CTA), почему сработало, эмбеддинг.
- **Инструменты:** скачивание видео (через сервис данных), ElevenLabs Scribe / Deepgram Nova-3 (речь),
  Gemini Pro (видео целиком), эмбеддинги OpenAI / Cohere / Voyage. Пилот: vidIQ `watch_shortform_content`.
- **Модель:** Sonnet — вывод «почему сработало» и разметка структуры.
- **Качество:** транскрипт дословный; структура размечена по таймкодам; есть тег формата
  («уровни», «до/после», «разбор ошибки»…) для поиска по смыслу.

### ✍️ A4. Сценарист — рерайт под бренд
- **Вход:** `breakdowns` + бренд-платформа (для кого, обещание, против чего, голос, отличие) +
  `playbook_weights` (что уже работало у этого бренда).
- **Выход:** `scripts`: 3 варианта сценария на один прецедент — хук, текст по таймкодам, визуал,
  CTA/кодовое слово, цель ролика (медиа или продажа), ссылка на прецедент.
- **Модель:** Sonnet (основной), Opus — премиум-клиенты и сложные случаи.
- **Встроенные проверки (до показа человеку):**
  - сходство с оригиналом по эмбеддингам — **не выше порога** (нет копии 1:1);
  - тон бренда — Haiku по 5 строкам платформы;
  - правдивость: нет выдуманных цифр и результатов;
  - у ролика есть понятная цель и путь к продаже (из ролика / через профиль / через базу).
- **Правила:** продукт встроен естественно; медиаконтент не продаёт в лоб; разные CTA на разных копиях.

### ✅ Утверждение — человек
- **Кто:** клиент или менеджер Syneps.
- **Где:** дашборд MarketerOC (`dashboard/`), позже — Telegram-бот.
- **Действия:** утвердить / править / отклонить с причиной. Причины отказа идут в обучение Сценариста.
- **Смета:** перед утверждением показывается стоимость производства.

### 🎬 A5. Продюсер — произвести
- **Вход:** утверждённый `scripts`.
- **Выход:** `productions`: файлы видео, обложки, варианты для клонов.
- **Три маршрута:**
  1. **Живая съёмка:** карточка задачи (сценарий, ТЗ, суфлёр) → человек снимает → монтаж.
  2. **Генерация:** Hypit + HypiHub (Seedance, GPT Image, голос, WhisperX) — сборка ролика по сценарию.
  3. **Клоны:** ffmpeg, без нейросетей — исходники (оригинал + зеркало + пересъёмки) × ~60 вариантов кадра.
- **Модель:** Sonnet управляет Hypit; сама генерация — внешние модели.
- **Правила:** AI-контент не должен выглядеть как «ИИ-мусор»; бюджет и смета от Оркестратора.

### 📤 A6. Публикатор
- **Вход:** `productions`.
- **Выход:** `publications`: аккаунт, время, CTA/кодовое слово, UTM, исходник.
- **Инструменты:** Metricool (`createScheduledPost`, лучшее время), Threads API.
- **Правила клонов:** 8–9 пробных публикаций в день; ротация исходников A1 → B1 → C1 → A'1;
  Instagram «склеивает» исходник примерно после 50 публикаций → смена исходника; кодовое слово
  не на каждой копии; разные CTA.
- **Ручная кнопка «стоп»** на любой серии.

### 📊 A7. Аналитик результатов — замкнутый цикл
- **Вход:** `publications`.
- **Выход:** `publication_stats` (6 / 24 / 72 ч / 7 дней), `playbook_weights` бренда.
- **Инструменты:** Metricool аналитика, Instagram Graph API, бот кодовых слов (заявки).
- **Логика:** какие структуры, хуки, форматы и CTA дали досмотры, сохранения, репосты, заявки →
  повышает их вес при следующем отборе (A2) и рерайте (A4). Симптомы склейки клонов → сигнал Публикатору.
- **Модель:** формулы + Sonnet для вывода «почему».

### 🧠 A8. Стратег (SynOC Marketer)
- **Роль:** раз в неделю смотрит весь конвейер бренда глазами маркетолога: стадия проекта,
  самый ранний сломанный слой воронки, доля медиа/продаж, что масштабировать, что выключить.
- **Инструкция:** `brain/synoc-marketer-instruction.md`.
- **Модель:** Opus.
- **Выход:** недельный отчёт + изменение приоритетов для A1–A7. Сейчас для самого Syneps это
  уже работает как еженедельный обзор по расписанию (понедельник 9:54 МСК).

## 4. Статусы

**Ролик-прецедент:** `found → measured → candidate → rejected | broken_down`
**Сценарий:** `draft → checked → awaiting_approval → approved | changes_requested | rejected`
**Производство:** `queued → producing → ready → failed`
**Публикация:** `scheduled → published → measured_6h → measured_24h → measured_72h → final`

Оркестратор двигает объект дальше, только когда предыдущий статус закрыт.

## 6. Где нужен человек

| Точка | Почему |
|---|---|
| Подключение бренда: платформа, сегмент, бюджет | Без этого всё остальное мимо |
| **Утверждение сценария** | Правило Syneps: генерация только после утверждения |
| Смета производства выше лимита | Деньги |
| Живая съёмка | Снимают люди |
| Ответы тёплым лидам и созвоны | Продажа — люди (бот квалифицирует, человек закрывает) |
| Стоп серии клонов | Риск бана / склейки |

## 7. Модели и стоимость

| Задача | Модель | Почему |
|---|---|---|
| Чистка списков, табу-фильтр, тон | Claude Haiku / Gemini Flash | Массово и дёшево |
| Разбор «почему сработало», сценарии, управление Hypit | Claude Sonnet | Качество текста и логики |
| Премиум-сценарии, стратегия бренда | Claude Opus | Сложные решения |
| Речь в текст | ElevenLabs Scribe / Deepgram | Лучше под русский |
| Видео целиком | Gemini Pro | Смотрит ролик полностью |
| Поиск по смыслу, сходство | Эмбеддинги OpenAI / Cohere / Voyage | — |

Генерация для клиента — по кредитам, цена = себестоимость × 3 (раздел 17). Каждый платный вызов — в `spend`.

## 8. Два уровня реализации

### Уровень 1 — сейчас: связка для самого Syneps (без разработки продукта)
Агенты = чаты Claude Code по направлениям + задачи по расписанию + файлы в репозитории.

| Агент | Как работает сейчас |
|---|---|
| Скаут, Аналитик | vidIQ в чате; позже HikerAPI |
| Разборщик | vidIQ `watch_shortform_content` → `reels/*.md` |
| Сценарист | Claude в чате «Контент-завод» по `CLAUDE.md` |
| Утверждение | Ник в чате |
| Продюсер | Hypit + HypiHub в сессии |
| Публикатор | Metricool в чате |
| Аналитик результатов, Стратег | Ежедневный и еженедельный обзоры по расписанию |

Цель уровня 1 — проверить каждый шаг на трафике Syneps и собрать реальные пороги и промпты.

### Уровень 2 — продукт для клиентов
Тот же контракт данных, но кодом на сервере Syneps:
- агенты — воркеры на **Claude Agent SDK / Claude API** с инструментами (HikerAPI, STT, Hypit, Metricool);
- Supabase — данные и очередь; Оркестратор — сервис со статусами и лимитами;
- дашборд MarketerOC — утверждение, сметы, статистика;
- несколько брендов параллельно, изоляция данных между брендами.

## 10. Риски и ограничения

- **Правила площадок:** данные — только через сервисы данных и официальные API; публикации — через
  Metricool / официальные API; без серых автоботов, автокомментов и массового спама.
- **Авторское право / FTC:** клонируем структуру, а не чужие материалы; сходство под контролем (A4).
- **Склейка клонов:** мониторинг показов у копий, ротация исходников.
- **Бюджет:** лимиты на бренд, смета перед генерацией, журнал `spend`.
- **Качество AI-контента:** AI-фабрики конвертируют в 7–10 раз хуже живого (выводы VOIS) → AI как
  полигон для тестов, победителей переносим на живых людей и UGC.
- **Конкуренты:** данные клиентов не грузим в сторонние сервисы аналитики роликов.
