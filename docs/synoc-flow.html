1. Обзор и статус

SynOC — система, которая находит вирусные Reels в нише клиента, вытаскивает их структуру, пишет новый сценарий под бренд, производит ролик и учится на статистике клиента.

1. Найти блоги→ 2. Вирусные ролики→ 3. Сценарий→ 4. Рерайт→ 5. Производство→ 6. Замкнутый цикл

Текущая стадия: ручной пилот (MVP без разработки). Шаги выполняются вручную в сессии Claude Code через подключённые сервисы. Автоматизации (база, планировщик, скрипты) пока нет.

4. Hypit: установка и конфигурация

Hypit — open-source фреймворк, через который ИИ-агент производит видео. Видео описывается на языке SVML/SVS/SVRun, события привязаны к словам, а не к секундам. Модели подключаются через Providers (HypiHub или BYOK).

4.1 Установка (выполнено)

# Skill для агента (ставится в ~/.agents/skills/hypit)
npx -y skills add hypit-ai/hypit -g -y

# Исполняемый файл
npm install --global @hypit/hypit        # → @hypit/hypit 0.3.1

# Видео-проект
mkdir -p /home/user/hypit-studio && cd /home/user/hypit-studio
# package.json с { "hypit": { "project": true } }
hypit runtime init                       # → hypit.runtime.json

# Ключ HypiHub (импорт из файла, файл сразу удаляется)
hypit auth login hypihub.default --from <keyfile>

# Локальные программы: Chrome Headless Shell, OpenCV (uv)
NODE_USE_ENV_PROXY=1 hypit runtime up
NODE_USE_ENV_PROXY=1 hypit doctor

4.2 Runtime Profile (hypit.runtime.json)

{
  "format": "hypit.runtime-local@1",
  "dataRoot": ".hypit/runtimes/local",
  "credentials": { "local": { "use": "@hypit/credential-store-local" } },
  "endpoints": {
    "hypihub.default":    { "use": "@hypit/provider-hypihub",
                            "config": { "baseUrl": "https://hypit.ai",
                                        "apiKey": { "store": "local", "key": "hypihub.oauth" } } },
    "media.local":        { "use": "@hypit/media-local" },
    "html.local":         { "use": "@hypit/provider-html-local" },
    "image.opencv.local": { "use": "@hypit/provider-image-opencv-local" }
  }
}

4.4 Важные нюансы

  • Прокси: Node fetch не читает HTTPS_PROXY. Все команды hypit, ходящие в сеть, запускать с NODE_USE_ENV_PROXY=1 (Node ≥ 22.21). Без этого: ENOTFOUND hypit.ai.
  • Эфемерность: облачный контейнер временный. Установка, проект и ключ живут только в текущей сессии. В новой сессии повторить 4.1 или вынести установку в Setup script окружения.
  • Альтернативные провайдеры: @hypit/provider-hiapi, -pollo, -beatapi, -monid, -tokendance (отдельная установка + запись в Profile).
  • Лицензия: модифицированная Apache 2.0. Внутреннее и клиентское использование разрешено; мультитенантный SaaS и перепродажа требуют коммерческой лицензии. Логотип в CLI и отчётах удалять нельзя. Выходные видео принадлежат пользователю.

4.5 Использование

/hypit Сделай клон ролика https://www.instagram.com/reel/<shortcode>/
Тема: <продукт и ЦА>. Сначала покажи план и смету.

Агент обязан показать план и стоимость до любых платных вызовов. Ориентир по примерам Hypit: около $1–1,2 за ролик 18–26 секунд.

6. Метрики и формулы

МетрикаФормулаПорог / применение
Медиана аккаунтаmedian(просмотры последних N роликов, без закрепов)База для сравнения
Выше нормы (outlier)просмотры ÷ медиана> 3× → в отбор
СкоростьΔпросмотров ÷ Δчасов между замерамиНужны повторные замеры (Supabase)
Вовлечённость (ER)(лайки + комменты) ÷ просмотрыПилот: 0,5–1,7%
НакруткаER аномально низкий при высоких просмотрахПорог подобрать на данных
Охват от базымедиана ÷ подписчикиДиагностика «выгорания» аудитории
Комменты ÷ лайкикомменты ÷ лайки≈ 1 → комментарии от кодового слова
Закрепы исключать из медианы и outlier-расчёта: они старые и искажают базу. Ролики младше 24–48 ч не сравнивать с остальными, их цифры ещё растут.

10. Безопасность

Ключ HypiHub был отправлен в чат открытым текстом. Он сохранён в истории сессии. Рекомендуется перевыпустить ключ в кабинете hypit.ai и хранить новый только в настройках окружения (Network secrets / Environment variables) или в Credential Store Hypit.

  • Ключи не коммитить, не передавать аргументами команд, не вставлять в чат.
  • Environment variables окружения видят все его пользователи; для секретов предпочтительнее Network secrets.
  • Все платные генерации — только после показанной сметы и подтверждения.
